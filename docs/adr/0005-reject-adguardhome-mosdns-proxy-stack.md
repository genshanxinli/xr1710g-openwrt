# ADR 0005 — 拒绝「AdGuardHome + mosdns + 代理核心」三板斧叠加

**Status**: accepted（2026-09-11 评审确定；`plan/03` D10 = 只出 ADR + 带证据裁决，**不落地任何 DNS 组件**）
**Context**:
社区流传的「三板斧」接法是：**mosdns 做分流中枢 → AdGuardHome 做过滤/统计面板 → 代理核心（mihomo/sing-box）做 fake-ip 与连接层分流**。
本机处境与它冲突的地方有三条硬条件：

1. **fake-ip 属于代理核心的 DNS 模块**，是架构 C 的组成部件（ADR-0003）——名单客户端拿 `198.18.x` 才能让代理侧零嗅探；
2. **只读固件卷 `fit` 余量极小**（原 32 KiB；本轮才靠恢复页扩容解决，ADR-0004），任何"再叠两个 Go 进程"的方案都只能走运行期安装到 overlay；
3. **本项目的第一不变量是"故障域最小"**，且本机有 09-09 事故史（数据缺失 → mosdns 起不来 → dnsmasq 指向死端口 → 全网断解析）。

**Decision**:
**拒绝三板斧叠加。** 具体地：

- 引入 mosdns：**否决**（与代理核心的 DNS 模块逐项重叠，是纯冗余）；
- 引入 AdGuardHome：**默认否决**；只有"明确要一个过滤/统计面板"时才考虑，且**不得同时**引入 mosdns；
- 拦被代理域名的广告：**正确工具是代理核心的连接级 REJECT 规则**（`rule-providers` + `RULE-SET …, REJECT`），**不是任何 DNS 层组件**；
- 本轮**不在固件或设备上落地 AGH / mosdns 的任何组件**（与 `plan/03` §5 一致）。

### 四条硬约束（若将来仍要上任何 DNS 前置 hub，任一不满足即不可上）

1. hub **不缓存**（fake-ip 默认 TTL 仅 1 秒 ⇒ 前置缓存价值归零，且必须显式关）；
2. hub **不得**对 fake-ip 域名返回真实 IP（否则破坏 fake-ip 语义）；
3. 若用 mosdns，**名单数据必须先就绪**，首启闸门（数据缺失则不接管）必须写进 `uci-defaults`；
4. **guard 必须把新端口纳入心跳链**，否则又多一个"指向死端口"的黑洞。

**Why**:

### 决定性理由：DNS 层组件看不见 fake-ip 域名

被代理域名在代理核心的 DNS 模块里就被本地 fake-ip 化（`withFakeIP` 在**任何上游查询之前**拦截 A/AAAA）⇒
AGH/mosdns 这类"DNS 前置层"**根本收不到这些查询**：

- 它们**拦不住**被代理域名上的广告；
- 若它们越权返回真实 IP，就**破坏 fake-ip 语义**（社区原话：「SmartDNS 产生的真实 IP 会与 FakeIP 机制冲突」）；
- 同型旁证：nikki maintainer 在 issue #423 的定性——「插件是通过防火墙规则劫持 DNS 请求，不会经过 dnsmasq」；
  把这条结论前移到**任何** "DNS 前置层" 都成立。

而连接级 `REJECT` 在**连接层**拒绝，**对被代理域名同样生效**，且**零新增进程**。这是"用对层"而不是"加组件"。

> ⚠️ **术语迁移（本仓库口径）**：E4/E11 的原始表述以 mihomo 为代理核心。
> 本分支的代理核心是 **sing-box**（ADR-0003），但**结构同型**、结论逐条成立：
> sing-box 的 `dns.servers` 里 fakeip 同样是"在上游查询之前拦截"，`route.rules` 同样提供连接级
> `action: reject`。所以"DNS 层过滤看不见 fake-ip 域名"与"连接级 REJECT 才有效"这两条**不随核心而变**。
> 本 ADR 引用原文时保留 mihomo 字样，并在应用结论处显式换到 sing-box。

**Considered Options**:

| 选项 | 内容 | 判定 |
|---|---|---|
| **P2（采纳）** | **不加任何组件**：代理核心连接级 REJECT 去广告（含被代理域名），geodata 自更新 | ✅ 0 新进程、0 新 feed。加权分 **38.05~38.5**（≥ 基线） |
| P1 | 只加 AGH 要面板：关代理核心 DNS 劫持 → 客户端走 AGH:53 → AGH 转发 `127.0.0.1#<代理DNS端口>`（fake-ip 仍归代理核心），AGH 缓存必须关 | ❌ 加权分 35.35（**低于不加**）；且关劫持后硬编码 DNS 的客户端绕过，规则匹配变弱 |
| P1′ | AGH 作为代理核心的上游（不关劫持）：只对真实解析域名过滤 | ❌ 被代理域名的广告**拦不住**（E4）+ 多一跳 |
| P3 | 完整三板斧（mosdns + AGH + 代理核心） | ❌ 加权分 **32.00**（越加越差）：+2 个 Go 进程 + 社区 feed + boot 期数据依赖 |
| 保持现状（不加） | 只保留 dnsmasq 兜底 + 代理核心 DNS | ✅ 本轮基线 |

**Consequences**:

- ✅ **DNS 关键路径保持 2 个组件**（dnsmasq + 代理核心），故障域最小；09-09 事故面不回归；
- ✅ 被代理域名的广告**能**拦住（走连接层 REJECT），比任何 DNS 层方案都完整；
- ⚠️ **没有查询统计面板**。这是明确接受的代价；若将来真要面板，按 P1 接法 + 四条硬约束 + `15.6` 的五条验收重新评审；
- ⚠️ 本 ADR **不**声称"未证实项已被证实"——E12 的三条未证实（接线顺序、AGH 长期稳定性、规则集体积）依然挂着；
- ⚠️ 若未来引入任何 DNS 前置 hub，**必须先过四条硬约束**，且 guard 的心跳链要同步扩（第 4 条）。
