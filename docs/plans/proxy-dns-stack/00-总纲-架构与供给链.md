## 2. 对外接口与数据模型（全部运行期可装卸）

### 2.1 UCI：`/etc/config/xr1710g_proxy`

| 选项 | 默认 | 语义 |
|---|---|---|
| `global.enabled` | `0` | **总开关**。`0` 时 init 立即退出，不建表不建路由不起进程 |
| `global.proxy_hosts` | 空 list | **名单客户端**（源 IP/网段）。v1 只按源分流 |
| `global.dns_scope` | `proxy_hosts` | fake-ip 作用域，只允许 `proxy_hosts`（架构 C 的核心约束） |
| `global.singbox_dns_port` | `5333` | sing-box DNS 监听端口（名单客户端 `:53` 经 nft redirect 到此） |
| `global.sinbox_tun` | `singtun0` | TUN 接口名 |
| `global.cn_list_url` | 见 `01-方案一` §4 | CN 名单抓取地址 |
| `global.cn_list_update` | `0` | 是否启用定时更新（默认关，只用只读快照） |
| `global.fwmark` | `0x40` | 策略路由标记（启动时检测冲突） |
| `global.route_table` | `100` | 策略路由表号（启动时检测冲突） |
| `global.fail_mode` | `open` | sing-box/DNS 不健康时的行为：**撤表撤规则，名单客户端退回直连** |

### 2.2 nft：独立表 `inet xr1710g_proxy`

**绝不写进 `inet fw4`**（`fw4 reload` 会 flush + 重建硬件 flowtable，正是 issue #7 的触发面）。

```nft
table inet xr1710g_proxy {
    set proxy_hosts { type ipv4_addr; flags interval; }      # 由 uci 生成
    set china_ip4   { type ipv4_addr; flags interval; }      # 快照 + 运行期更新 + dnsmasq nftset
    set china_ip6   { type ipv6_addr; flags interval; }

    chain dns_redirect {                                      # nat，仅名单客户端
        type nat hook prerouting priority dstnat - 5; policy accept;
        ip saddr @proxy_hosts meta l4proto { tcp, udp } th dport 53 redirect to :5333
    }

    chain capture {                                           # filter，路由判定前
        type filter hook prerouting priority mangle; policy accept;
        ip  saddr @proxy_hosts ip  daddr @china_ip4 accept    # 国内 → 直连 → 保 offload
        ip6 saddr @proxy_hosts ip6 daddr @china_ip6 accept
        ip  saddr @proxy_hosts meta mark set 0x40             # 其余 → 送 TUN
        ip6 saddr @proxy_hosts meta mark set 0x40
    }
}
# 名单外客户端：不匹配任何规则 → 原 forward 路径 → flow add @ft → PPE/NPU（100% 保留）
```

> 实现时以模板 + `nft -f` 单批载入；`stop` 用 `nft delete table inet xr1710g_proxy` 精确回收。

### 2.3 策略路由

```sh
ip rule add fwmark 0x40/0x40 table 100
ip route add default dev singtun0 table 100
```

- **启动前必须检测冲突**：Tailscale 占 `0x80000/0xff0000` + table 52（F9）；sing-box 自身默认 table 2022 / rule 9000。冲突即拒绝启动并落日志，不改他人条目。
- `stop` 逐条删除自建 rule/route。

### 2.4 只读资产与运行态

| 类别 | 位置 | 性质 |
|---|---|---|
| CN 名单快照 | `/usr/share/xr1710g-proxy/china_ip{4,6}.txt` | 随包进**只读 squashfs** ⇒ **零 NAND 写入、零 overlay 占用** |
| 运行态 | `/tmp/xr1710g-proxy/`（`config.json`、`cache_file`、日志、更新后名单、`state`） | tmpfs，掉电即失 |

| LuCI | `luci-app-xr1710g-proxy`（`packages-xr1710g/`，src-link 供给、锁源） | 开关 / 名单 / 更新 / 状态 |

## 3. 硬约束与不变量（可静态 grep 门禁）

| # | 不变量 | 门禁 |
|---|---|---|
| I1 | **不写 `flow_offloading*`** | `grep -rn 'flow_offloading' files/ packages-xr1710g/ scripts/` 只允许出现在只读展示/验收脚本；写路径出现即红 |
| I2 | **不 reload fw4** | proxy 相关代码中 `grep -rn 'firewall reload\|/etc/init.d/firewall'` 必须为空 |
| I3 | **nft 文件不碰 fw4 / 不动卸载点** | 任何 `.nft` 不得含 `table inet fw4`、不得含 `flow add` |
| I4 | **默认不接管** | `uci-defaults` 不得 `enable` 任何服务、不得写 `firewall`/`network` 的 offload 字段 |

> 这四条同时是 CI 门禁与 code review 清单；任一条被破坏 = 直接打回。

## 4. 固件布局与供给链

### 4.1 `fit` 扩容机制（源码实证）

**不改 DTS、不新增 installer、不硬编码容量常数。** HTTP U-Boot 恢复页的固件上传路径：

1. `recovery_calc_rebuild_ubi_limit()` 算出可容纳上限（= `avail_pebs` + 将被移除卷的 PEB）；
2. `image_size > limit` → 打印 `Image size ... exceeds target size ...` 并返回 `-EFBIG`；
3. `recovery_prepare_ubi_target()`：UBI 不可挂载则**整段擦除重建布局**；
4. `recovery_cleanup_ubi_firmware()`：**移除除 `ubootenv`/`ubootenv2`/`factory` 外的所有卷**（含旧 `fit` 与 `rootfs_data`）→ 释放 PEB；
5. `image_size > cur_size` → `recovery_resize_ubi_target()` → `ubi_resize_volume(DIV_ROUND_UP(image_size, usable_leb_size))`；
6. `recovery_ensure_rootfs_data()`：`rootfs_data` 以 size=0 创建 → **吃掉剩余全部 PEB**。

⇒ **上传更大的 `*-sysupgrade.itb` 即自动扩容 `fit`、自动缩 `rootfs_data`。**

**两个必须写进文档的后果：**

- ⚠️ **恢复页刷写会清空 `rootfs_data`（overlay / 全部配置）** —— 这是 `recovery_preserve_ubi_volume()` 白名单的必然结果，不是 bug。刷前必须备份 `/etc/config`。
- ⚠️ **布局选择器必须选 UBI 2.0**（`part="ubi"`，对应 `mtd2` `0x1b700000`）。选 1.5/1.0 会落到更小的分区 → `not enough PEBs`。

### 4.2 唯一必改项：`DEVICE_COMPAT_VERSION` 2.0 → 3.0

`patches/root/9000-xr1710g-common.patch`：

```
-DEVICE_COMPAT_VERSION := 2.0
+DEVICE_COMPAT_VERSION := 3.0
 DEVICE_COMPAT_MESSAGE := 容量布局变更：需经 HTTP U-Boot 恢复页（布局选择器 UBI 2.0）重刷；
                          该路径会清空 overlay，请先备份 /etc/config。
```

**为什么必须升**：第 4.1 步 5 只在恢复页路径生效；在旧布局（`fit` 206 LEB）设备上跑 in-OS `sysupgrade` 新的大镜像，会走到 `ubiupdatevol` 失败。升 compat 让 `sysupgrade` **在动手前干净拒绝**，而不是写到一半失败。

### 4.3 预装封闭清单（`config/seed-config.diff`）

| 包 | 理由 |
|---|---|
| `kmod-wireguard` | 内核态 WG（方案二硬要求，G3） |
| `kmod-ipset` + `kmod-ipt-ipset` | netbird ACL 依赖既有 `kmod-wireguard` 缺失项（解 openwrt/packages #7134：缺 ipset 时 ACK 规则**静默回滚为空**） |
| `kmod-tun` | sing-box TUN 入站（F6 已在，显式固化） |
| `kmod-nft-tproxy` | 本轮不用，但为将来 TProxy/homeproxy 留路（成本极低） |
| `sing-box` | 方案一核心 |
| `netbird` | 方案二核心（**自持提版 0.78.1**，官方 feed 0.73.2 是 #6953 内存泄漏版本） |
| `luci-app-xr1710g-proxy` | 方案一极简前端（`packages-xr1710g/`，src-link） |
| 排障工具 | `ip-full`（`ip rule/route table X`，busybox ip 不支持）、`tcpdump`、`ethtool`、`conntrack-tools`、`yq` |

> kmod 用 `=y`：既进镜像，又在 `bin/targets/airoha/an7581/kmods/<ver>-<hash>/` 产出 `.apk`（两个目标同时满足）。
> **尺寸不硬编码**：镜像实际大小由 HTTP U-Boot 自动适配；CI 只做「比上一版大」的提醒（§4.5）。

### 4.4 kmods / 包 feed（CI → Release 附件）

- `.github/workflows/build.yml` 增一步：把 `bin/targets/airoha/an7581/kmods/` 与自建 `packages/` 打包为 pre-release 附件（沿用现有 `ci-<run_number>` 流水线）。
- 设备侧写 `/etc/apk/repositories.d/customfeeds.list`（该文件 sysupgrade 默认保留）。
- **规则**：内核跳版 ⇒ config hash 变 ⇒ kmod 必须随新 Release 重装（写进 `docs/`）。

### 4.5 CI 尺寸自检

- 报告 `.manifest` 的 Installed-Size 累加与 `fit` 余量；
- 镜像比上一版大时，release notes 标注：**「本版需经 HTTP U-Boot 恢复页重刷（现有 `fit` 卷装不下；该路径会清空 overlay，请先备份配置）」**。

## 5. 边界情况与失败模式

| 场景 | 行为 |
|---|---|
| `enabled=0`（默认 / 全新刷机） | init 立即退出；无 nft 表、无 ip rule、无进程 |
| sing-box 启动失败 / 崩溃 | guard 撤 `dns_redirect` + `capture` 表 → 名单客户端退回直连 + dnsmasq（**fail-open**）；非名单客户端全程无感 |
| `kmod-tun` 缺失（内核跳版后） | 拒绝启动并落明确日志；不留任何半配置 |
| fwmark / table 冲突（Tailscale / 未来 pbr） | 启动前检测 → 拒绝启动，提示改 uci |
| 名单变更 | 新连接立即生效；**已卸载的旧流不会即时改道**（offload 后报文绕过 netfilter）→ 提供**定向**清相关 conntrack（不做全表 flush） |
| IPv6 | `china_ip6` + `ip6 daddr` 对称；AAAA 不做任何劫持 |
| 客户端绕过路由 DNS（DoH / 硬编码 IP / ECH） | 名单客户端 → 落代理侧（方向安全）；非名单客户端 → 照旧直连 + offload |
| 无 RTC 导致名单更新 TLS 失败 | 只用只读快照，不阻塞启动 |
| 重启 | 状态全在 `/tmp`；init 启动时**先清自己的表再建**，不留残留 |
| 卸载 | `apk del` + init `stop` + `nft delete table` + 删 `ip rule/route`，回到与基线**逐字节一致**的 `nft list ruleset` / `ip rule show` |

## 6. 风险与未决项

| 风险 | 等级 | 处置 |
|---|---|---|
| 恢复页刷写**会清 overlay**（F3） | 高（操作面） | `FLASHING.md` 显著警告 + release notes + T0 备份 |
| 后续镜像**再变大**时 in-OS `sysupgrade` 失败（`fit` 卷已被上次刷机定死） | 中 | CI 尺寸自检（§4.5）；失败即走恢复页重刷（会清 overlay） |
| netbird 0.78.1 自持提版的 `PKG_HASH` / Go 可复现性 | 中 | 锁源铁律：实算 `PKG_MIRROR_HASH` 并登记 FIXES；CI 复验 |
| NEON 可能因 SIMD 状态保存/恢复开销反而变慢 | 中 | 只在 `#EXP`；A/B 无收益即不毕业（研究明令「禁止凭理论直接进 default」） |
| CN 名单源与许可证未取证 | 中 | 实施首步先取证（抓取 + 计数 + 许可证 + 更新频率）；结果入 FIXES 后再固化 |
| 名单 IP 级 geo 误判（CDN / anycast） | 低 | `dnsmasq --nftset` 域名级补充 + 允许手工追加；文档写明已知边界 |

| issue #7 未修 | 中 | 本分支**不碰** `flow_offloading*`；9036/9037 保持 `#EXP` |
