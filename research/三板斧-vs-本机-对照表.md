## 1. 能力矩阵（谁在哪一层工作）

| 能力 | **本分支代理核心**（sing-box） | AdGuardHome | mosdns |
|---|---|---|---|
| 国内外分流 | ✅ DNS 层 `dns.rules` + 连接层 `route.rules` | ⚠️ 仅上游组粗分 | ✅ geosite 分流（主场） |
| 上游加密（DoH/DoT/DoQ） | ✅ | ✅ | ✅ |
| 内存缓存 | ✅（`cache_file` 在 `/tmp`） | ✅ **但必须关**（E8） | ✅ **同理必须关** |
| fake-ip | ✅ **唯一归属**（`dns.servers` 的 `fakeip` 类型） | ❌ 与 fake-ip 冲突 | ✅ 有 fakeip 插件 → 就是"双 fake-ip"反模式 |
| **域名过滤 / 去广告** | ✅ **连接级** `rule_set` + `action: reject`（**对 fake-ip 域名同样生效**，E4） | ✅ DNS 级（**只对真实解析域名有效**，E4） | ✅ DNS 级（同限） |
| geodata 自取/更新 | ✅（快照随包 + 运行期更新到 `/tmp`） | — | ⚠️ 需外部名单数据，**boot 期依赖**（E7） |
| 查询统计 / 面板 | ⚠️ 只有连接级日志 | ✅ **主场** | ⚠️ 弱 |
| 运行期写盘 | ✅ 全在 `/tmp`（G2） | ❌ overlay（≈28.7 MiB，E5） | ❌ overlay（15–25 MB，E5） |
| 在官方 feed | ✅（sing-box 1.14.0） | ✅（adguardhome 0.107.79） | ❌ **不在任何官方 feed**（E7） |

**读法**：mosdns 与代理核心的 DNS 模块**逐项重叠**，唯一独有的是"DNS 层 IP 标记/并发测速择优"；
AGH 独有的是"过滤规则生态 + WebUI 统计"。
⇒ **要过滤面板就只加 AGH；mosdns 是纯冗余**（E3）。

## 2. 决定性机制（为什么 DNS 前置层不管用）

```
被代理域名的查询路径：
  客户端 → [nft redirect] → 代理核心 DNS:5333 → **fakeip 在访问上游之前拦截** → 返回 198.18.x
                                              ↑
                              AGH / mosdns 装在这个位置之后 ⇒ 永远收不到该查询（E4）

正确去广告路径（连接级）：
  客户端 → 代理核心 route.rules（rule_set 命中 category-ads-all）→ action: reject
                                              ↑
                              在连接层拒绝 ⇒ **对 fake-ip 域名同样生效**，且零新增进程（E4）
```

三条硬事实：

1. `withFakeIP` 在**任何上游查询之前**拦截 A/AAAA（E4）⇒ 前置 hub 收不到被代理域名的查询；
2. hub 若越权返回真实 IP ⇒ **破坏 fake-ip 语义**（社区原话：「SmartDNS 产生的真实 IP 会与 FakeIP 机制冲突」，E2）；
3. 「插件是通过防火墙规则劫持 DNS 请求，不会经过 dnsmasq」（nikki maintainer, issue #423）—— 前移到**任何** DNS 前置层都成立（E4）。

## 4. 叠加的真实代价（按本机口径，逐条可复核）

| 代价 | 数字 / 依据 | 出处 |
|---|---|---|
| 装不进只读固件卷 | AGH apk 11.1 MB / Installed **28.7 MiB**；mosdns Go **15–25 MB** ⇒ 合计 ≈50 MiB，只能运行期装 overlay（占 350 MiB 的 ~14%，一次性写 ≈22 s @ 实测 **2.26 MB/s**）⇒ **破坏"镜像可复现 + 锁源"铁律** | E5 |
| 故障域 ×3 | DNS 关键路径从 1+1 变 +3；单上游死端口 → **静默 35 s 超时**；上游列表为空 → **0.0 s REFUSED** | E6 |
| 09-09 事故同型风险 | mosdns **不在官方 feed**，geosite/geoip 是 boot 期依赖 —— 上次断网正是"数据缺失 + dnsmasq 指向死端口" | E7 |
| 缓存必须关 | fake-ip TTL 默认 **1 秒** ⇒ 前置缓存价值归零（OpenClash shipped 做法亦要求 `cachesize=0`） | E8 |
| 双份真相 | DNS 层分流与连接层分流不一致 ⇒ "解析走直连、连接却走代理"经典疑难 | E9 |

## 5. 若将来仍要上（四条硬约束 + 五条验收）

**四条硬约束（任一不满足即不可上）**（E10）：
1. hub **不缓存**；2. hub **不得**对 fake-ip 域名返回真实 IP；
3. 若用 mosdns，**名单数据必须先就绪**，首启闸门写进 `uci-defaults`；4. **guard 把新端口纳入心跳链**。

**五条验收**（`DNS方案深度调研` §15.6）：① 过滤有效性**双侧判据**（国内直连广告域名 + 走代理广告域名都要拦）；
② `dig www.google.com @<路由>` 仍返回 `198.18.x`（fake-ip 未被破坏）；③ 连续两次查询不返陈旧 fake-ip（缓存确已关）；
④ 守卫覆盖：新端口进心跳，重复 N-1/N-1b 演练确认任一层挂掉都能回落 dnsmasq；⑤（仅 mosdns）断网冷启动确认"数据未就绪 → 不接管"。
